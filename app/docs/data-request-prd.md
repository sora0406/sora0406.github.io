# <a name="_vipprmtyrj8s"></a>**1. 產品概述**
## <a name="_otbwkznbse6y"></a>1.1 目的和描述
- **痛點**：專案管理人員(PGM)目前缺乏一個集中化的平台來管理對供應商的數據要求。這些需求通常是通過郵件、電話或會議分散管理，缺乏統一的追蹤和提醒機制，導致數據收集效率低下，回應率不佳，並消耗大量人力進行追蹤。

- **解決方案**：數據要求管理模組旨在提供一個中央化平台，讓專案管理人員能夠建立表單、選擇供應商、發送通知、追蹤回應狀態，並接收和審核數據。系統將自動化大部分追蹤和提醒工作，提高數據收集的效率和完整性。

- **價值主張**：
  - 縮短數據收集週期40%
  - 提高數據完整性和質量50%
  - 節省管理人員20%的工作時間
  - 提供數據收集過程的可視化和分析

## <a name="_8b29y9y6l7dd"></a>1.2 市場研究文件
- **請參考** {{市場研究文檔連結}}
  - **開發團隊重點**：
    - 競品分析顯示現有解決方案缺乏全面的通知和提醒功能
    - 供應商反饋顯示簡潔的表單界面和分階段保存功能是關鍵需求
    - 企業級用戶重視數據安全和系統整合能力

## <a name="_gfibadgniy68"></a>1.3 成功指標
- **定量指標**：
  - 數據收集完成率提高至少30%
  - 數據收集週期縮短至少40%
  - 供應商滿意度調查達到80%以上的正面評價
  - 數據質量問題減少50%
  - 管理人員工作效率提升至少20%

- **定性指標**：
  - 改善供應商資料提交體驗
  - 提高數據收集流程的透明度
  - 增強專案管理人員對數據收集過程的控制力

### <a name="_6ld36mgfudfp"></a>[US-DR-01] 專案管理人員 - 建立數據要求表單
作為專案管理人員(PGM)，

我希望能夠建立自定義的數據要求表單，

以便能夠向供應商收集特定格式和內容的數據。

**接受標準**
*請參考i18n[` `**連結**](https://docs.google.com/spreadsheets/d/1CLg5JL9LxTRFbSmLWy8qPqmnsKGI1D5w3f1RaT_-5IQ/edit?usp=sharing) 和 [\[Common Terms\] 重點名稱&功能敘述標準化＿共編整理表 _更新版](https://docs.google.com/spreadsheets/d/1u8y4ytQncwvqXqcH_MBFruer88EKQLopuiuutrNXLbo/edit?usp=sharing) 進行相關標籤、下拉選項等翻譯*

*請參考設計準則 [**連結**](https://www.figma.com/design/8hBgFAnEk5inQfRZeeC7J6/CarbonM-Design-System?node-id=2898-66370&t=Bcc7Q3Anhp9tjkRx-1) 確保行為遵循相同規則*


1. **表單建立界面**

   輸入:
   - 表單名稱：必填，文字，最大長度50字元，預設值為空
   - 表單描述：非必填，文字區域，最大長度500字元，預設值為空
   - 要求類別：必填，選項(基本資訊、組織溫室氣體、產品碳足跡)，預設為空
   - 截止日期：必填，日期選擇器，需晚於當前日期
   - 到期前提醒：必填，多選選項(1天前、3天前、1週前)，預設值為「3天前」
   - 優先級：必填，選項(高、中、低)，預設值為「中」

   輸出:
   - 成功創建的表單模板，包含所有設定的欄位和配置
   - 表單ID和創建時間戳記
   - 通知提示「表單已成功創建」

2. **添加表單欄位**

   輸入:
   - 欄位類型：必填，選項(文本、數字、日期、檔案、複選框、單選按鈕、下拉選單、文字區域)
   - 欄位名稱：必填，文字，最大長度30字元
   - 欄位描述：非必填，文字，最大長度100字元
   - 是否必填：必填，複選框，預設值為非必填
   - 驗證規則：非必填，取決於欄位類型(如數字範圍、檔案類型限制)

   輸出:
   - 表單中加入新欄位
   - 即時預覽欄位在表單中的顯示效果

3. **預覽要求內容**

   輸入:
   - 預覽按鈕：必填，按鈕操作
   - 切換檢視模式：非必填，選項(供應商視角、管理員視角)

   輸出:
   - 表單預覽顯示，與供應商將看到的格式一致
   - 可捲動的完整表單內容
   - 返回編輯按鈕


### <a name="_6ld36mgfudfp"></a>[US-DR-02] 專案管理人員 - 選擇目標供應商
作為專案管理人員(PGM)，

我希望能夠選擇需要回應數據要求的供應商，

以便將我的數據要求精確發送給相關供應商。

**接受標準**

1. **查看邊界供應商清單**

   輸入:
   - 邊界選擇：必填，下拉選單(所有供應商、範疇1/2/3供應商、關鍵供應商)
   - 搜索關鍵字：非必填，文字，最大長度50字元
   - 供應商類別：非必填，多選下拉選單
   - 地區：非必填，多選下拉選單
   - 產品線：非必填，多選下拉選單
   - 過往回應率：非必填，範圍選擇(0%-100%)

   輸出:
   - 符合邊界與篩選條件的供應商列表
   - 每個供應商顯示其名稱、ID、類別、過往回應率
   - 可分頁瀏覽結果，每頁顯示20家供應商

2. **批量選擇供應商**

   輸入:
   - 供應商選擇：必填，複選框列表，可多選
   - 全選/取消全選：非必填，複選框
   - 批量匯入：非必填，CSV檔案上傳

   輸出:
   - 已選供應商數量統計（顯示於頁面上方）
   - 已選供應商列表，可查看和移除
   - 匯入成功/失敗提示（如使用批量匯入）

3. **進入下一步**

   輸入:
   - 下一步按鈕：必填，按鈕操作（當已選供應商數量>0時啟用）

   輸出:
   - 保存選擇的供應商並進入第二步
   - 顯示選擇的供應商數量提示


### <a name="_6ld36mgfudfp"></a>[US-DR-03] 專案管理人員 - 發送要求和追蹤回應
作為專案管理人員(PGM)，

我希望能夠發送數據要求通知並追蹤供應商的回應狀態，

以便有效管理數據收集進度並確保及時完成。

**接受標準**

1. **送出數據要求**

   輸入:
   - 確認發送：必填，按鈕操作
   - 添加個性化訊息：非必填，文字區域，最大長度300字元
   - 通知語言：必填，選項(中文、英文、雙語)，預設為「雙語」
   - 發送方式：必填，選項(電子郵件、系統通知、兩者)，預設為「兩者」
   - 發送時間：非必填，日期時間選擇器，預設為當前時間

   輸出:
   - 發送進度指示
   - 發送完成確認，包含成功發送數量
   - 發送失敗列表(如有)
   - 自動跳轉至要求清單頁面

2. **檢視所有要求**

   輸入:
   - 狀態篩選：非必填，選項(全部、進行中、已完成、已過期)
   - 類別篩選：非必填，選項(全部、基本資訊、組織溫室氣體、產品碳足跡)
   - 日期範圍：非必填，日期範圍選擇器
   - 排序方式：非必填，選項(創建時間、到期日、完成率)

   輸出:
   - 要求清單，包含要求名稱、類別、創建時間、到期日、完成率
   - 每個要求的操作按鈕(查看詳情、更多操作)
   - 可分頁瀏覽結果

3. **回應狀態追蹤**

   輸入:
   - 選擇要查看的要求：必填，從清單中選擇
   - 供應商狀態篩選：非必填，選項(全部、未開啟、已查看、進行中、已提交、逾期)
   - 供應商搜索：非必填，文字搜索

   輸出:
   - 供應商回應狀態儀表板
   - 各狀態供應商數量和百分比統計
   - 詳細供應商列表，包含狀態和最後活動時間
   - 可排序和導出的數據表格


### <a name="_6ld36mgfudfp"></a>[US-DR-04] 專案管理人員 - 管理要求詳情
作為專案管理人員(PGM)，

我希望能夠管理已發送的數據要求及其詳情，

以便靈活調整要求參數並維護要求狀態。

**接受標準**

1. **檢視單一要求詳情**

   輸入:
   - 選擇要查看的要求：必填，從清單中選擇或點擊"查看詳情"按鈕

   輸出:
   - 要求基本資訊（名稱、類別、創建時間、描述等）
   - 要求狀態概況（完成率、回應率等）
   - 供應商回應狀態列表
   - 表單內容預覽
   - 更多操作下拉選單

2. **更新要求參數**

   輸入:
   - 更多操作下拉選單：必填，選擇"更新截止日"或"更新提醒日"
   - 新截止日期：條件性必填，日期選擇器
   - 新提醒設定：條件性必填，多選選項(1天前、3天前、1週前)
   - 更新原因：非必填，文字區域

   輸出:
   - 參數更新確認
   - 系統自動發送更新通知給受影響的供應商
   - 更新記錄添加到版本歷史

3. **管理要求狀態**

   輸入:
   - 更多操作下拉選單：必填，選擇"設定要求完成"或"刪除要求"
   - 確認對話框：必填，確認操作
   - 完成備註：條件性必填（如選擇設定完成），文字區域

   輸出:
   - 狀態更新確認
   - 自動通知受影響的供應商（如適用）
   - 更新記錄添加到版本歷史

4. **檢視版本紀錄**

   輸入:
   - 更多操作下拉選單：必填，選擇"檢視版本紀錄"

   輸出:
   - 時間軸顯示的版本歷史
   - 每個版本的變更詳情
   - 變更人員和時間
   - 可切換查看不同版本的表單內容


### <a name="_6ld36mgfudfp"></a>[US-DR-05] 專案管理人員 - 審核提交數據
作為專案管理人員(PGM)，

我希望能夠審核供應商提交的數據並提供反饋，

以便確保收集到的數據符合質量標準和需求。

**接受標準**

1. **查看提交數據**

   輸入:
   - 選擇需要審核的提交：必填，從列表中選擇
   - 篩選條件：非必填，多種篩選選項(供應商、日期、狀態等)

   輸出:
   - 完整的提交內容顯示，包括所有欄位和附件
   - 與原始要求的比較視圖
   - 提交的歷史版本(如有多次提交)

2. **進行審核評估**

   輸入:
   - 審核結果：必填，選項(接受、拒絕、需要修改)
   - 審核評論：條件性必填(如選擇「拒絕」或「需要修改」)，文字區域
   - 評分(可選)：非必填，1-5星評分

   輸出:
   - 審核結果保存確認
   - 通知提示「審核已完成」

3. **要求修改或補充資料**

   輸入:
   - 需要修改的欄位：必填，複選框列表
   - 修改說明：必填，文字區域，針對每個需要修改的欄位
   - 修改截止日期：必填，日期選擇器

   輸出:
   - 修改請求發送確認
   - 修改請求記錄在通訊歷史中


### <a name="_6ld36mgfudfp"></a>[US-DR-06] 供應商 - 查看和提交數據
作為供應商，

我希望能夠查看數據要求、填寫表單並提交所需資料，

以便及時響應客戶的數據需求。

**接受標準**

1. **查看數據要求**

   輸入:
   - 登入供應商門戶：必填，用戶名和密碼
   - 選擇數據要求：必填，從待處理列表中選擇

   輸出:
   - 數據要求詳細信息，包括描述、截止日期和優先級
   - 需要填寫的表單結構
   - 任何附加說明或參考資料

2. **填寫數據表單**

   輸入:
   - 表單欄位：根據表單定義，必填和選填欄位
   - 上傳文件：根據需求上傳檔案，支援拖放功能
   - 添加備註：非必填，文字區域

   輸出:
   - 表單填寫進度指示
   - 欄位驗證反饋
   - 保存進度確認(如選擇暫存)

3. **提交數據**

   輸入:
   - 確認提交：必填，確認對話框
   - 最終檢查：系統提供的填寫完整性檢查

   輸出:
   - 提交確認訊息
   - 提交回執，包含提交ID和時間戳
   - 可選的保存提交內容PDF選項


### <a name="_6ld36mgfudfp"></a>[US-DR-07] 管理層 - 查看數據收集分析
作為高級管理層，

我希望能夠查看數據收集的統計和分析報告，

以便了解供應鏈數據收集的整體效率和完成情況。

**接受標準**

1. **數據收集概況儀表板**

   輸入:
   - 時間範圍：必填，日期範圍選擇器，預設為過去30天
   - 數據類別：非必填，多選下拉選單
   - 視圖類型：必填，選項(趨勢圖、對比圖、明細表)，預設為「趨勢圖」

   輸出:
   - 主要指標摘要：完成率、平均回應時間、數據質量評分
   - 視覺化圖表，根據選定的視圖類型
   - 趨勢分析和歷史比較

2. **供應商參與度分析**

   輸入:
   - 供應商篩選：非必填，多種篩選條件
   - 排序方式：必填，選項(回應率、速度、數據質量)，預設為「回應率」
   - 顯示數量：必填，選項(前10、前20、全部)，預設為「前10」

   輸出:
   - 供應商排名列表
   - 參與度評分和關鍵指標
   - 可導出Excel或PDF的報表

3. **合規和風險報告**

   輸入:
   - 風險層級：非必填，選項(高、中、低、全部)，預設為「全部」
   - 合規類別：非必填，多選下拉選單
   - 報告格式：必填，選項(摘要、詳細)，預設為「摘要」

   輸出:
   - 風險評估摘要
   - 合規狀態概況
   - 需要關注的重點領域和供應商
   - 可導出的風險報告

# <a name="_s413q4hnatsk"></a>**4. 其他備註**

## 4.1 技術考量

- 系統必須支持大規模併發用戶訪問，特別是在數據收集截止日期前
- 文件存儲需考慮加密和安全性
- 需評估現有通知系統的整合能力和限制
- 考慮數據導出和API接口的需求，特別是對於與其他企業系統的整合
- 確保版本控制系統能夠記錄所有要求變更歷史

## 4.2 未來可能的擴展

- 機器學習輔助的數據驗證和質量檢查
- 供應商協作功能，允許多個供應商共同提交相關數據
- 更高級的數據視覺化和分析工具
- 移動應用程序支持，特別是針對供應商使用場景
- 基於歷史數據的智能表單推薦系統

## 4.3 實施優先順序

1. 核心表單建立和供應商選擇功能
2. 兩步驟發送要求流程
3. 通知發送和狀態追蹤系統
4. 要求詳情管理功能
5. 供應商提交界面
6. 審核和反饋功能
7. 報告和分析工具

以上功能按重要性和相依性排序，建議按此順序實施以確保系統的核心價值盡快實現。
